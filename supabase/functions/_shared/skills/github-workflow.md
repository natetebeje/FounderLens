## Creating a PR — Step by Step

### Step 1: Get the SHA of main branch HEAD
```
GET /repos/natetebeje/FounderLens/git/ref/heads/main
→ Returns: { object: { sha: "abc123..." } }
```

### Step 2: Create a new branch
```
POST /repos/natetebeje/FounderLens/git/refs
Body: {
  "ref": "refs/heads/feat/your-feature-name",
  "sha": "<sha from step 1>"
}
```

Branch naming:
- New feature: `feat/description-in-kebab-case`
- Bug fix: `fix/description`
- Refactor: `refactor/description`
- Docs/skills: `docs/description`

### Step 3: Create or update each file
```
PUT /repos/natetebeje/FounderLens/contents/<path/to/file.tsx>
Body: {
  "message": "feat: add new component",
  "content": "<base64 encoded file content>",
  "branch": "feat/your-feature-name",
  "sha": "<existing file SHA if updating — omit if creating new file>"
}
```

For multiple files, repeat Step 3 for each file on the same branch.

### Step 4: Open the Pull Request
```
POST /repos/natetebeje/FounderLens/pulls
Body: {
  "title": "feat: <concise description>",
  "body": "<PR description — see format below>",
  "head": "feat/your-feature-name",
  "base": "main"
}
→ Returns: { number: 42, html_url: "https://github.com/natetebeje/FounderLens/pull/42" }
```

## PR Title Format

Follow conventional commits:
- `feat: add weekly CEO digest email`
- `fix: correct Paperclip agent role enum values`
- `refactor: extract AICompaniesTab into separate component`
- `docs: add architecture skill file for agents`

## File Content Rules

When creating or editing files via the GitHub API:
1. Read the existing file first to get its SHA (needed for updates)
2. Encode content as base64: `btoa(unescape(encodeURIComponent(content)))` in JS/TS
3. Always create files in the correct directory matching the architecture skill
4. New React pages must also add a route in `src/App.tsx`
5. New Edge Functions must be deployed separately via Supabase CLI

## Deploying after merge

After the founder merges a PR, deployment happens by running on the VPS:
```bash
ssh root@31.97.146.40 /opt/deploy-founderlens.sh
```

This:
1. `git pull origin main` — fetches latest
2. `npm install --legacy-peer-deps` — installs deps
3. `npm run build` — Vite builds to `dist/`
4. `cp -r dist/* /var/www/founderlens/` — deploys

The Engineer agent can note this in the PR body so the founder knows what to run after merging.
